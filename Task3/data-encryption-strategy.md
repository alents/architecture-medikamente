# Стратегия защиты данных

## 1. Классификация данных

| Класс | Уровень чувствительности | Описание | Примеры данных |
|-------|--------------------------|----------|----------------|
| **К1 — Специальные ПДн** | Критический | Медицинские данные, врачебная тайна | Медицинские карты, результаты анализов, диагнозы, заключения врачей, информация о хронических заболеваниях |
| **К2 — Общие ПДн** | Высокий | Персональные данные, позволяющие идентифицировать субъекта | ФИО, дата рождения, телефон, e-mail, адрес прописки, место работы/учёбы, данные договоров |
| **К3 — Финансовые данные** | Высокий | Платёжная информация и бухгалтерские данные | Данные ККМ, платёжные транзакции, зарплатные ведомости, налоговая отчётность, данные 1С |
| **К4 — Операционные данные** | Средний | Внутренние данные бизнес-процессов | Журналы записей к специалистам, расписание врачей, учёт ТМЦ, реестры анализов, внутренняя переписка |


## 2. Автоматизированный контроль

### 2.1. Мониторинг и обнаружение угроз

| Средство | Назначение | Контролируемые данные |
|----------|------------|----------------------|
| **Wazuh** (open-source SIEM/XDR) | Централизованный сбор и корреляция событий безопасности. Файловый мониторинг (FIM) — отслеживание изменений в файлах с ПДн. Обнаружение аномалий | Логи доступа к файлам, БД, API; попытки несанкционированного доступа; изменения конфигураций |
| **OpenSearch** | Хранение и индексация логов, полнотекстовый поиск по событиям безопасности | Все логи от Wazuh, логи приложений, логи API-запросов |
| **Victoria Metrics + Grafana** | Мониторинг инфраструктуры + сводная панель: метрики серверов, истечение TLS-сертификатов, ключевые ИБ-алерты из OpenSearch | Метрики серверов, СУБД, приложений; агрегированные алерты Wazuh |
| **Расширенный аудит Windows Server** (встроенный) | Аудит доступа к файлам с ПДн на файловом сервере, аудит входов/выходов в AD, изменений групповых политик | Логи доступа к файлам, события аутентификации |

### 2.2. Предотвращение утечек (DLP)

| Средство | Назначение | Контролируемые каналы |
|----------|------------|----------------------|
| **Staffcop Enterprise** | Предотвращение утечек конфиденциальных данных + мониторинг действий сотрудников | E-mail, веб-трафик, USB-устройства, печать, буфер обмена, мессенджеры |

### 2.3. Управление ключами и сертификатами

| Средство | Назначение |
|----------|------------|
| **КриптоПро CSP 5.0** | ГОСТ-шифрование, электронная подпись, TLS по ГОСТ. Управление сертификатами для подписания документов и отчётности |
| **Рутокен ЭЦП 3.0** | Аппаратное хранение ключей шифрования и ЭП. Двухфакторная аутентификация для администраторов и врачей при доступе к К1-данным |
| **cert-manager** (для Kubernetes) | Автоматический выпуск и ротация TLS-сертификатов для сервисов |
| **Orion Soft StarVault** | Хранение секретов приложений (API-ключи, пароли БД), автоматическая ротация. Централизованное управление ключами шифрования pgcrypto |

### 2.4. Контроль в CI/CD

| **SonarQube** (Community Edition) | Статический анализ кода: поиск захардкоженных секретов, проверка корректности работы с шифрованием |
|----------|------------|
| **Политики Kubernetes** (встроенные NetworkPolicy + OPA/Kyverno) | Запрет запуска контейнеров без TLS, ограничение сетевого доступа между сервисами, обязательное шифрование volumes |

## 5. Итоговая таблица: Данные → Необходимость защиты → Инструменты

| Данные | В чём необходимость защиты | Инструменты защиты |
|--------|---------------------------|-------------------|
| **Медкарты, результаты анализов, диагнозы** (К1) | ФЗ-152 ст.10 (специальные ПДн), ФЗ-323 ст.13 (врачебная тайна), Приказ ФСТЭК №21 (УЗ-1). Максимальный ущерб: штрафы до 18 млн ₽, уголовная ответственность, отзыв лицензии | **At rest:** pgcrypto (шифрование столбцов в PostgreSQL), BitLocker (диски сервера). **In transit:** TLS 1.3 (Angie), SSL PostgreSQL, WireGuard/ViPNet (филиалы). **Контроль:** Wazuh (аудит доступа), Staffcop (DLP), Рутокен 3.0 (2FA для доступа к данным), КриптоПро CSP 5.0 (ГОСТ-подпись документов) |
| **ПДн пациентов: ФИО, телефон, e-mail, адрес** (К2) | ФЗ-152 ст.18.1, ПП РФ №1119 (УЗ-2/3). Штрафы, репутационные потери, отток клиентов | **At rest:** pgcrypto, BitLocker. **In transit:** TLS 1.3 (Angie), Android Keystore / iOS Keychain (моб. приложение). **Контроль:** Keycloak (RBAC/ABAC), Staffcop (DLP), Wazuh, AD-политики |
| **Платёжные данные, бухгалтерия, зарплаты** (К3) | ФЗ-54 (ККТ), НК РФ, ФЗ-161 (НПС). Финансовые потери, штрафы ФНС | **At rest:** BitLocker (сервер 1С → PostgreSQL), Кибер Бэкап (шифрованные бэкапы). **In transit:** TLS 1.3 (платёжный шлюз), токенизация карт. **Контроль:** Wazuh, аудит Windows Server |
| **Журналы записей, расписание, ТМЦ** (К4) | ФЗ-98 (коммерческая тайна), косвенно содержат ПДн. Сбой бизнес-процессов при утечке | **At rest:** BitLocker. **In transit:** SMB 3.0 Encryption (AD), WireGuard (филиалы). **Контроль:** аудит Windows Server, Victoria Metrics + Grafana, OpenSearch |
| **Ключи шифрования, секреты API** (мета-уровень) | Компрометация ключей = компрометация всех зашифрованных данных | **At rest:** Рутокен ЭЦП 3.0 (мастер-ключи), Orion Soft StarVault (секреты приложений). **In transit:** mTLS между Vault и сервисами. **Контроль:** аудит Vault, автоматическая ротация ключей |
| **Данные в мобильном приложении** (К2) | Утечка при утере/краже устройства клиента | **At rest:** Android Keystore / iOS Keychain. **In transit:** TLS 1.3, Certificate Pinning. **Контроль:** минимизация кэша, отсутствие ПДн в push-уведомлениях |
| **Логи аудита** (мета-уровень) | Целостность логов — основа расследования инцидентов. Подделка скрывает следы атак | **At rest:** отдельный том с ограниченным доступом, BitLocker. **In transit:** TLS (syslog → Wazuh). **Контроль:** append-only политики, репликация логов в изолированный сегмент |
