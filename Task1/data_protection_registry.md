## Реестр данных пациентов и способы защиты

### Идентификационные данные

| # | Тип данных | Способ защиты | Обоснование |
|---|-----------|---------------|-------------|
| 1 | ФИО | **Обезличивание (токенизация)** | ФИО — главный прямой идентификатор. Токенизация позволяет работать с записями пациента по токену, не раскрывая личность. Оригинал ФИО доступен только через token vault авторизованным ролям |
| 2 | Дата рождения | **Обезличивание (токенизация)** | В сочетании с ФИО однозначно идентифицирует человека. Токенизация разрывает эту связь. Для аналитики можно выдавать возрастную группу из vault без раскрытия точной даты |
| 3 | Телефон | **Обезличивание (токенизация) + Маскирование** | В базах и системах хранится токен. В списках пациентов телефон не отображается (Data Minimization — не нагружать vault избыточными запросами). В карточке конкретного пациента приложение запрашивает vault и показывает маску `+7 (***) ***-45-67`. Полный номер раскрывается по явному действию сотрудника с логированием в audit. |
| 4 | Электронная почта | **Обезличивание (токенизация) + Маскирование** | Аналогично телефону: в базах — токен, в списках не отображается, в карточке пациента — маска `i***@mail.ru`. Полный адрес — по явному действию с логированием. Сервис уведомлений получает оригинал из vault по токену в момент отправки |

### Расширенные данные

| # | Тип данных | Способ защиты | Обоснование |
|---|-----------|---------------|-------------|
| 5 | Адрес прописки | **Обезличивание (токенизация)** | Содержит точное местоположение субъекта. Токенизация позволяет при необходимости (выезд на дом) раскрыть адрес авторизованному сотруднику через vault |
| 6 | Место работы / учёбы | **Обфускация** | Данные избыточны для целей медицинского обслуживания (Data Minimization). Рекомендуется прекратить сбор. Для уже накопленных данных — необратимая обфускация |

### 2.3. Медицинские данные

| # | Тип данных | Способ защиты | Обоснование |
|---|-----------|---------------|-------------|
| 7 | Хронические заболевания | **Шифрование** | Врачу необходим доступ к полным данным для принятия медицинских решений. Шифрование at rest с разграничением доступа по ролям |
| 8 | Результаты анализов | **Шифрование** | Врач и пациент (через ЛК) должны видеть фактические значения показателей. Шифрование at rest + in transit, доступ по роли (лечащий врач, пациент) |
| 9 | Медицинские заключения (JPG, PDF) | **Шифрование** | Файлы-документы, которые должны быть доступны в оригинальном виде врачу и пациенту. Шифрование файлов at rest, расшифровка только при авторизованном доступе |
| 10 | Медицинская карта (совокупность записей) | **Шифрование** | Агрегированная сущность, содержащая медицинскую историю. Шифрование at rest, доступ строго по RBAC (лечащий врач + пациент) |

### Данные о записях и визитах

| # | Тип данных | Способ защиты | Обоснование |
|---|-----------|---------------|-------------|
| 11 | Запись к специалисту (дата, время, врач, пациент) | **Обезличивание (токенизация)** | Связка «пациент + врач-специалист» косвенно раскрывает медицинскую информацию. Пациент идентифицируется по токену. Ресепшен получает полное ФИО через vault, так как роль имеет право на раскрытие для выполнения рабочих задач |
| 12 | История визитов пациента | **Обезличивание (токенизация)** | История визитов привязывается к токену пациента. Полная история раскрывается только самому пациенту (ЛК) и лечащему врачу через vault |

### Финансовые данные пациентов

| # | Тип данных | Способ защиты | Обоснование |
|---|-----------|---------------|-------------|
| 13 | Платежи за услуги (сумма, дата, услуга, пациент) | **Обезличивание (токенизация)** | Привязка платежа к пациенту — через токен. Бухгалтерия работает с номером договора и суммами без доступа к ФИО |
| 14 | Клиентский договор | **Шифрование** + **Обезличивание (токенизация)** | Договор содержит полные ПДн и подпись — шифрование at rest. В системах учёта договор идентифицируется по токену, а не по ФИО пациента |

### Данные интеграции с лабораторией (планируемые)

| # | Тип данных | Способ защиты | Обоснование |
|---|-----------|---------------|-------------|
| 15 | Направление на анализ | **Обезличивание (токенизация)** | В API-контракте пациент идентифицируется только токеном. Лаборатория не получает ФИО — только токен и тип анализа |
| 16 | Результат анализа из лаборатории | **Шифрование** + **Обезличивание (токенизация)** | Результат — медицинские данные, нужны в исходном виде врачу. Шифрование in transit (mTLS) и at rest. Привязка к пациенту — по токену, без передачи ФИО через API |
